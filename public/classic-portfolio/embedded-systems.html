How I think

Make it clear. Make it testable.

Good embedded work begins with a simple signal path and grows through testing. I enjoy diagnosing faults, tuning behaviour and learning why a system responds the way it does — the debugging is often where the real understanding happens.

That approach keeps the build honest: if I can't explain a reading or a reaction, I'm not done with it yet.

Workflow

How a build comes together.

A repeatable loop keeps the complexity manageable, whether it's a one-day experiment or a longer project.

01 / MAP

Define the signal chain

Write down inputs, decisions and outputs before touching a breadboard.

02 / WIRE

Build the smallest version

Prototype one stage at a time so a fault is easy to isolate.

03 / VERIFY

Test in the real world

Check behaviour with actual sensors and loads, not just simulation.

04 / REFINE

Tune and document

Adjust thresholds, tidy the logic and make the result repeatable.
